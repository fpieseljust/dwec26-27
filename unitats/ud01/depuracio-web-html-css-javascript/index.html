Depuració de codi web amb el navegador i VS Code¶

Objectius¶

En acabar aquesta guia sabràs:

  • Identificar errors d’HTML, CSS i JavaScript.
  • Utilitzar les eines de desenvolupador del navegador.
  • Posar punts d’interrupció i executar JavaScript pas a pas.
  • Depurar una pàgina web des de Visual Studio Code.
  • Aplicar un mètode ordenat per trobar i corregir errors.

Idea clau: depurar no és provar coses a l’atzar. És observar què passa, formular una hipòtesi, fer una prova i comprovar el resultat.

HTML estructura el contingut, CSS defineix l’aparença i JavaScript afegeix comportament i interactivitat. [web:1]

1. Què significa depurar?¶

Depurar és el procés de localitzar, entendre i corregir errors d’un programa.

Un error pot ser:

  • De sintaxi: el navegador no entén una instrucció.
  • De lògica: el programa funciona, però fa una cosa incorrecta.
  • De dades: una variable conté un valor inesperat.
  • D’integració: dos fitxers o parts del programa no es comuniquen correctament.
  • Visual: la pàgina es veu malament, encara que no aparega cap error.

Exemple¶

const preu = 10;
const quantitat = 3;

console.log(preu + quantitat); // 13, però probablement volíem 30

El codi és vàlid, però la lògica no és la que esperàvem:

console.log(preu * quantitat); // 30

2. Preparar un projecte senzill¶

Crea una carpeta amb aquests tres fitxers:

projecte-web/
├── index.html
├── styles.css
└── script.js

index.html¶

<!doctype html>
<html lang="ca">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Exemple de depuració</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <main>
    <h1>Comptador</h1>
    <p id="valor">0</p>
    <button id="incrementar">Incrementar</button>
  </main>

  <script src="script.js"></script>
</body>
</html>

styles.css¶

body {
  font-family: system-ui, sans-serif;
  max-width: 40rem;
  margin: 3rem auto;
  padding: 1rem;
}

#valor {
  font-size: 3rem;
  color: darkblue;
}

script.js¶

const valorElement = document.querySelector('#valor');
const botoElement = document.querySelector('#incrementar');

let valor = 0;

botoElement.addEventListener('click', () => {
  valor++;
  valorElement.textContent = valor;
  console.log('Valor actual:', valor);
});

Obri index.html amb el navegador i comprova que el botó incrementa el número.

3. Depurar amb les eines del navegador¶

Els navegadors moderns incorporen eines de desenvolupador per inspeccionar la pàgina carregada, el DOM, els estils i l’execució de JavaScript. [web:2]

Obrir les eines¶

Pots obrir-les de diverses maneres:

  • Clic dret sobre la pàgina i selecciona Inspecciona.
  • Prem F12.
  • Prem Ctrl + Shift + I en Windows o Linux.
  • Prem Cmd + Option + I en macOS.

Els noms exactes poden variar segons el navegador.

Panells principals¶

Panell Utilitat
Elements o Inspector Examinar i modificar l’HTML i el CSS del DOM actual.
Console Consultar errors i executar JavaScript.
Sources o Debugger Veure fitxers, posar breakpoints i executar pas a pas.
Network Comprovar peticions, fitxers que no carreguen i respostes del servidor.
Application/Storage Inspeccionar cookies, localStorage i altres dades.
Performance Analitzar el rendiment de la pàgina.

4. Depurar HTML¶

Què cal comprovar?¶

  • Les etiquetes estan ben tancades.
  • Els elements estan dins del lloc correcte.
  • Els atributs tenen el nom i el valor correctes.
  • Els identificadors (id) són únics.
  • Els fitxers CSS i JavaScript estan ben enllaçats.
  • Els elements que JavaScript busca existeixen realment.

Inspeccionar el DOM¶

  1. Obri les eines de desenvolupador.
  2. Entra en el panell Elements o Inspector.
  3. Utilitza el selector d’elements.
  4. Fes clic sobre el component que vols estudiar.
  5. Observa l’estructura HTML que el navegador ha construït.

El DOM és la representació en memòria de la pàgina que el navegador està utilitzant. No sempre coincideix exactament amb el text original del fitxer HTML.

Exemple d’error¶

<button id="incrementar">Incrementar</buton>

L’etiqueta de tancament és incorrecta. Cal escriure:

<button id="incrementar">Incrementar</button>

Fonts diferents¶

  • Veure codi font: mostra el document original rebut pel navegador.
  • Inspector/Elements: mostra el DOM actual, que pot haver estat modificat per JavaScript.

Aquesta diferència és útil quan JavaScript afegeix, elimina o canvia elements.

5. Depurar CSS¶

Inspeccionar estils¶

  1. Selecciona un element en el panell Elements.
  2. Mira les regles CSS aplicades.
  3. Observa les propietats ratllades: una altra regla té més prioritat.
  4. Desactiva temporalment propietats amb la casella corresponent.
  5. Modifica valors per experimentar.

Els canvis fets des de l’inspector són temporals. Per conservar-los, copia’ls al fitxer CSS.

Problemes habituals¶

Selector incorrecte¶

#titol {
  color: red;
}

<h1 id="title">Hola</h1>

Els identificadors no coincideixen: titol i title són diferents.

Propietat sobreescrita¶

p {
  color: red;
}

#valor {
  color: darkblue;
}

En aquest cas, el selector amb id sol tenir més especificitat i guanya.

Model de caixes¶

En inspeccionar un element, observa:

  • content: contingut.
  • padding: espai interior.
  • border: vora.
  • margin: espai exterior.

Si un element ocupa més o menys espai del que esperaves, revisa aquestes quatre zones.

Estils que depenen de l’estat¶

Per provar estats com :hover o :focus, força’ls des de l’inspector. Això permet estudiar un botó encara que el ratolí no estiga damunt.

6. Depurar JavaScript amb la consola¶

El panell Console mostra missatges, avisos i errors. També permet executar expressions JavaScript directament.

Missatges útils¶

console.log('El programa ha arribat ací');
console.warn('Aquest valor és inesperat');
console.error('No s’ha pogut completar l’operació');

Per estudiar valors:

console.log({ valor, valorElement, botoElement });

Això és més informatiu que escriure molts missatges separats.

Errors freqüents¶

Element inexistent¶

const boto = document.querySelector('#boto-inexistent');
boto.addEventListener('click', () => {});

Si no existeix l’element, boto val null i apareixerà un error semblant a:

Cannot read properties of null

Solució: comprova que l’id coincideix i que el script s’executa després de carregar l’HTML.

Fitxer no trobat¶

Si el navegador mostra un error 404 o no executa el codi, revisa:

<script src="script.js"></script>

El nom, les majúscules i la ubicació han de coincidir exactament.

Variable no definida¶

console.log(total);

Si total no s’ha declarat, apareixerà un ReferenceError.

7. Punts d’interrupció al navegador¶

Un breakpoint pausa l’execució en una línia concreta. Això permet observar l’estat del programa abans que continue.

Procediment¶

  1. Obri Sources o Debugger.
  2. Localitza script.js.
  3. Fes clic en el número de línia on vols pausar l’execució.
  4. Torna a la pàgina i provoca l’acció, per exemple, fes clic al botó.
  5. Quan el programa es pause, inspecciona les variables.

Controls principals¶

  • Resume: continua fins al pròxim breakpoint.
  • Step over: executa la línia actual sense entrar en les funcions.
  • Step into: entra dins de la funció que es crida.
  • Step out: ix de la funció actual.
  • Restart: reinicia l’execució.

Què observar?¶

  • Valors de les variables.
  • Call stack o pila de crides.
  • Arguments de les funcions.
  • Expressions en el panell d’observació.
  • Elements del DOM abans i després del canvi.

debugger¶

També pots posar un punt d’interrupció directament al codi:

botoElement.addEventListener('click', () => {
  debugger;
  valor++;
  valorElement.textContent = valor;
});

Quan les eines de desenvolupador estan obertes, el navegador s’aturarà en aquesta línia.

Recorda eliminar debugger quan acabes.

8. Depurar amb VS Code¶

VS Code permet editar el projecte, executar-lo i connectar el depurador amb un navegador basat en Chromium. En projectes senzills, el navegador continua sent el lloc on s’executa la pàgina, mentre que VS Code ofereix una interfície integrada per treballar amb el codi.

Preparació¶

  1. Obri la carpeta del projecte amb VS Code.
  2. Obri index.html i comprova els enllaços a CSS i JavaScript.
  3. Instal·la només les extensions que necessite el projecte. Per a HTML, CSS i JavaScript bàsic, sovint no cal cap extensió addicional.
  4. Inicia un servidor local si el projecte ho necessita.

Per a una pàgina estàtica, pots utilitzar una extensió de servidor local o executar un servidor senzill des del terminal:

python -m http.server 8000

Després obri:

http://localhost:8000

Un servidor local és preferible a obrir sempre el fitxer amb file://, especialment quan hi ha mòduls, peticions o recursos que requereixen HTTP.

Posar un breakpoint¶

  1. Obri script.js.
  2. Fes clic a l’esquerra del número de línia.
  3. Apareixerà un punt roig.
  4. Obri la vista Run and Debug.
  5. Selecciona una configuració de navegador disponible.
  6. Prem F5 o el botó d’inici.
  7. Interactua amb la pàgina fins que s’arribe al breakpoint.

Controls de VS Code¶

Control Funció
Continue Continua l’execució.
Step Over Executa la línia actual sense entrar en funcions.
Step Into Entra en la funció cridada.
Step Out Surt de la funció actual.
Restart Reinicia la sessió de depuració.
Stop Atura la sessió.

La vista de depuració també mostra variables locals, expressions observades, call stack i punts d’interrupció.

Breakpoints condicionals¶

Un breakpoint condicional només pausa si es compleix una condició.

Exemple:

if (valor === 10) {
  console.log('Hem arribat a 10');
}

També pots establir la condició des del menú contextual del breakpoint. És útil quan un bucle s’executa moltes vegades i només t’interessa estudiar un cas concret.

Logpoints¶

Un logpoint escriu informació sense pausar el programa. És una alternativa pràctica a afegir temporalment molts console.log al fitxer.

9. Errors de xarxa i recursos¶

Quan una pàgina no funciona, revisa també el panell Network.

Comprova:

  • Si styles.css i script.js retornen l’estat 200.
  • Si hi ha errors 404.
  • Si una petició està bloquejada.
  • Si el servidor retorna un tipus de contingut incorrecte.
  • Si una petició tarda massa o falla.

Un error típic és escriure:

<link rel="stylesheet" href="style.css">

quan el fitxer real es diu styles.css.

10. Mètode sistemàtic de depuració¶

Segueix sempre aquest ordre:

  1. Reprodueix l’error. Descobreix quins passos el provoquen.
  2. Descriu el comportament esperat. Què hauria de passar?
  3. Descriu el comportament real. Què passa exactament?
  4. Llig els missatges d’error. Comprova la consola i la xarxa.
  5. Redueix el problema. Elimina temporalment parts que no siguen necessàries.
  6. Inspecciona valors. Utilitza console.log, breakpoints o expressions observades.
  7. Formula una hipòtesi. Per exemple: “el selector no troba l’element”.
  8. Fes un únic canvi. Així sabràs què ha solucionat el problema.
  9. Torna a provar. Comprova també que no has introduït un error nou.
  10. Neteja el codi. Elimina missatges de prova i breakpoints innecessaris.

Canviar moltes coses alhora dificulta saber quin canvi ha funcionat.

11. Exercici guiat¶

Modifica el projecte perquè tinga un error intencionat:

const valorElement = document.querySelector('#valor');
const botoElement = document.querySelector('#incrementar');

let valor = 0;

botoElement.addEventListener('click', () => {
  valor++;
  valorElement.textContent = valor;
  console.log('Valor actual:', valor);
});

Canvia l’HTML així:

<p id="comptador">0</p>

Ara el botó deixarà de funcionar perquè JavaScript busca #valor, però l’HTML conté #comptador.

Tasques¶

  1. Reprodueix l’error fent clic al botó.
  2. Llig el missatge de la consola.
  3. Afig aquest missatge abans del listener:
console.log({ valorElement, botoElement });
  1. Comprova quin element val null.
  2. Corregeix l’id de l’HTML o el selector de JavaScript.
  3. Posa un breakpoint dins de la funció del clic.
  4. Verifica el valor de valor pas a pas.
  5. Elimina els missatges de diagnòstic que ja no necessites.

12. Llista de comprovació¶

HTML¶

  • Les etiquetes estan ben tancades.
  • Els id coincideixen amb els selectors JavaScript i CSS.
  • Els fitxers estan en la ubicació correcta.
  • El DOM conté els elements esperats.

CSS¶

  • El selector coincideix amb l’element.
  • La propietat no està ratllada per una altra regla.
  • La mida i l’espaiat són correctes.
  • S’han revisat margin, padding, border i box-sizing.
  • S’han comprovat els estats :hover i :focus.

JavaScript¶

  • No hi ha errors rojos en la consola.
  • Les variables tenen el valor esperat.
  • Els elements seleccionats no són null.
  • Els esdeveniments estan connectats.
  • Les funcions s’executen en l’ordre correcte.
  • Els breakpoints confirmen el flux del programa.

Recursos¶

  • Els fitxers carreguen amb estat 200.
  • No hi ha errors 404.
  • Les rutes respecten majúscules i minúscules.
  • El servidor local està funcionant.

Activitat final¶

Crea una aplicació amb:

  • Un camp de text.
  • Un botó per afegir tasques.
  • Una llista de tasques.
  • Un botó per eliminar cada tasca.

Introdueix deliberadament tres errors:

  1. Un selector CSS incorrecte.
  2. Un id que no coincideix entre HTML i JavaScript.
  3. Una operació lògica que produïsca un resultat incorrecte.

Per a cada error, lliura:

  • Una descripció del problema.
  • El missatge o símptoma observat.
  • L’eina utilitzada per trobar-lo.
  • La correcció aplicada.
  • Una captura o explicació del breakpoint, si n’has utilitzat un.

Idea final¶

Les eines de desenvolupador no substitueixen el raonament: ajuden a observar el programa. Un bon procés de depuració combina una descripció precisa del problema, una hipòtesi verificable i proves petites i controlades.
